# Дневники: «Тренировки» и «Рацион» (Android)

Два самостоятельных нативных приложения на Kotlin и Jetpack Compose. Перенос двух веб-прототипов
(`trenirovki.html`, `raciona.html` из <https://github.com/caftooz/diary>). Всё работает офлайн, без аналитики и сторонних SDK. Единственное обращение к сети — проверка и скачивание обновлений с GitHub (отключается в настройках).
Если установлены оба приложения, они показывают друг другу связанные данные (раздел «Обмен данными»).

## Структура репозитория

| Путь | Что внутри |
| --- | --- |
| `core/` | Общий модуль: собственная дизайн-система (фирменные палитры «Пульс» и «Свежесть», градиентные шапки, стеклянные карточки, фон со световыми пятнами; Material You — по желанию), шрифты Onest и Unbounded, графики на Canvas с градиентами, всплывающая панель снизу (`DiarySheet`) для форм и подробностей, элементы выбора (сегментный переключатель, плашки с буквами, шкала 1–5, плитки со значками, переключатель «вкл/выкл», отметки), общие компоненты, утилиты дат и JS-совместимых чисел, **контракт обмена данными** и клиент (`ru.diary.core.contract`) |
| `app-training/` | «Тренировки», пакет `ru.diary.training`: `domain` (правила, импорт/экспорт), `data` (Room, DataStore), `ui` (Compose), `rest` (таймер отдыха) |
| `app-nutrition/` | «Рацион», пакет `ru.diary.nutrition`, та же схема слоёв |
| `tools/golden/` | Node-скрипты, которые берут данные и эталонные результаты прямо из HTML-прототипов |
| `gradle/libs.versions.toml` | Каталог версий |

Архитектура: одна Activity, Navigation Compose, MVVM + Repository, `StateFlow`, корутины. DI ручной (`AppContainer`).
Хранение: Room (у каждого приложения своя БД, схемы экспортируются в `schemas/`) и DataStore для настроек.

### Данные из прототипа

Каталог упражнений, программы A/B/C, встроенные шаблоны планов и каталог блюд **не переписывались вручную**.
`tools/golden/gen.mjs` и `gen-nutrition.mjs` выгружают их из HTML в `catalog.json` (ресурсы приложений):

```
node tools/golden/gen.mjs <trenirovki.html> app-training
node tools/golden/gen-nutrition.mjs <raciona.html> app-nutrition
```

## Сборка

Нужны JDK 17+ (подойдёт JBR из Android Studio) и Android SDK с платформой 36.

```
# Windows, Git Bash
export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"
echo 'sdk.dir=C\:/Users/<вы>/AppData/Local/Android/Sdk' > local.properties   # файл в git не попадает

./gradlew assembleDebug        # оба приложения, debug
./gradlew lint                 # проверка lint
./gradlew assembleRelease      # release с R8 и сжатием ресурсов
```

APK: `app-training/build/outputs/apk/<тип>/` и `app-nutrition/build/outputs/apk/<тип>/`.
Идентификаторы: `ru.diary.training` и `ru.diary.nutrition`.

### Подпись release

Оба приложения **обязательно подписываются одним ключом**: от этого зависит обмен данными (signature-permission).
Ключ в репозиторий не коммитится (`*.jks`, `*.keystore`, `local.properties` в `.gitignore`).

```
keytool -genkeypair -v -keystore diary.jks -alias diary -keyalg RSA -keysize 4096 -validity 10000
```

Затем в `local.properties` (или переменными окружения с теми же именами):

```
DIARY_KEYSTORE=C\:/путь/к/diary.jks
DIARY_KEYSTORE_PASSWORD=...
DIARY_KEY_ALIAS=diary
DIARY_KEY_PASSWORD=...
```

Без этих значений release-сборка получается неподписанной (`*-release-unsigned.apk`).
Debug-сборки обоих приложений подписаны общим debug-ключом, поэтому обмен данными работает и в них.

## Продукты по штрих-коду и фото блюд («Рацион»)

* Кнопка «Сканировать» на вкладке «Блюда» открывает камеру (библиотека ZXing, без сервисов Google). Поддерживаются EAN-13, EAN-8, UPC и ITF;
  код можно ввести и вручную.
* Продукт сначала ищется в «Моих продуктах», затем (если включено в настройках) в открытой базе [Open Food Facts](https://openfoodfacts.org) —
  туда уходит только номер штрих-кода. Если продукта нет или данных не хватает, КБЖУ на 100 г вводятся с этикетки один раз и сохраняются.
* В дневник записываются граммы, ккал, белки, жиры и углеводы (в записи продукта `dish = "bc:<код>"`, `portion` — граммы).
  База обновлена до версии 2 (миграция без потери данных, покрыта тестом); экспорт JSON дополнен полями `fat`, `carbs` и списком `products`,
  записи блюд выгружаются как раньше.
* Фотографии встроенных блюд лежат в `app-nutrition/src/main/assets/dishes/` (WebP, ~600 КБ на все). Они взяты через [Openverse](https://openverse.org)
  из Flickr и Wikimedia Commons под лицензиями CC0, CC BY и CC BY-SA; блюда вырезаны (модель BiRefNet через rembg) и помещены на единый тёмный фон с одинаковым светом и тенью, 720×540. Авторы и ссылки — в `credits.json`
  и в приложении: Настройки → Фотографии блюд.

## «Взвесить», состав блюд и нормы («Рацион»)

* **Взвесить**: выбираете продукт (куриная грудка, помидор…) или однородное блюдо (плов, салат) и указываете граммы —
  калории, белки, жиры, углеводы, клетчатка и сахар считаются сами. В тот же список попадают «Мои продукты» по штрих-коду.
* База продуктов `app-nutrition/src/main/resources/ru/diary/nutrition/foods.json` (~100 позиций) собирается скриптом
  `tools/foods/gen.py` из [USDA FoodData Central](https://fdc.nal.usda.gov/) (SR Legacy, общественное достояние);
  творог, кефир, сметана и ряженка — по типичной российской этикетке.
* **Состав блюд** — `compositions.json`: граммы каждого продукта в порции. Из него считаются проценты («52% картофель, 41% минтай»),
  вес порции и пищевая ценность; строки состава в карточке блюда ведут к продукту во «Взвесить».
* Порция больше не выбирается: «Съел» записывает обычную порцию, точное количество — через «Взвесить».
* **Нормы на день** (калории, белки, жиры, углеводы, клетчатка) задаются в настройках; в дневнике видно «съедено / норма».
* База Room версии 3 (клетчатка у записей и продуктов), миграции 1 → 2 → 3 покрыты тестом.

## Блюдо по фото через Gemini («Рацион»)

* Кнопка «Блюдо по фото» на вкладке «Блюда»: снимок или фото из галереи отправляется в [Google Gemini API](https://ai.google.dev/gemini-api/docs),
  модель определяет продукты из встроенной базы и их граммы, а КБЖУ и клетчатка считаются по данным USDA, как во «Взвесить».
  Перед записью результат можно поправить: название, граммы каждого продукта, лишнее — убрать.
* Нужен собственный бесплатный ключ из [Google AI Studio](https://aistudio.google.com/apikey) (Настройки → Блюдо по фото).
  Ключ хранится зашифрованным (Android Keystore, AES-GCM) и никуда, кроме Gemini API, не передаётся.
* Наружу уходят только уменьшенное фото (до 1024 px, JPEG) и текст запроса со списком продуктов. Ответ — JSON по строгой схеме
  (`PhotoPrompt.schema`), запрос — Interactions API (`v1beta/interactions`), модели `gemini-3.8-flash` (по умолчанию) или `gemini-3.5-flash-lite`.
* Ограничения бесплатного уровня Google: API недоступен в ряде стран (в том числе в России), присланные данные могут использоваться
  для улучшения продуктов Google и просматриваться людьми, нужен возраст 18+, дневной лимит запросов обновляется в полночь по тихоокеанскому времени.

## Тренировка по этапам и схема мышц («Тренировки»)

* Тренировка идёт по этапам: разминка → список упражнений («Начать / Продолжить») → одно упражнение крупно
  (вес и повторы большими − / +, «Подход выполнен», «Как далось», список подходов, «Следующее упражнение»).
* У каждого встроенного упражнения есть схема работающих мышц: фигура спереди и сзади, основные мышцы ярко,
  вспомогательные бледнее. Она видна на экране упражнения («Работают мышцы» → полная схема), в каталоге при добавлении
  упражнения и в редакторе программы. У своих упражнений схемы нет.
* Контуры фигуры взяты из [react-body-highlighter](https://github.com/GV79/react-body-highlighter) (© 2020 GV79, MIT),
  разметка «упражнение → мышцы» и русские названия — в `app-training/src/main/resources/ru/diary/training/body.json`.
  Схема рисуется векторно (Compose Canvas) и подстраивается под светлую и тёмную тему.
* **Программы отдельно от плана.** План только ссылается на программы (день «Зал» берёт очередную или выбранную для дня).
  В «План → Программы»: очередь в зале с порядком ↑ ↓ (буквы A, B, C… перераздаются по порядку), «Заменить на готовую»
  (id, буква и место в очереди сохраняются, план не меняется), «Убрать из очереди», свои программы и библиотека готовых
  программ из `presets.json` (тяговые дни, классика зала, дома) — «В очередь» или «Отдельно».
* Классические упражнения для зала (жим штанги лёжа, бицепс с гантелями, становая, тяга штанги, жим ногами и др., 20 шт.)
  лежат в `gym.json` и добавляются к каталогу прототипа (`catalog.json` не трогаем — он генерируется). В окне
  «Добавить упражнение» есть поиск по названию и по мышцам. Веб-версия этих упражнений не знает: при переносе туда
  программы с ними теряют эти пункты.
* Подробные инструкции к шагам стойки на руках и упражнениям растяжки — в `guides.json` того же каталога.

## Обмен данными между приложениями

> **Сейчас обмен выключен** (`DiaryContract.SHARING_ENABLED = false`): приложения не читают друг друга, провайдеры отдают пустой ответ,
> а блоки «баланс дня», «питание» и «съедено и потрачено» скрыты. Чтобы включить обмен, поставьте `true` и выпустите новую версию.

Контракт описан в `core/.../contract/DiaryContract.kt` (версия контракта `1`).

* Каждое приложение держит `ContentProvider` (`exported=true`) с `readPermission` и custom-permission
  `protectionLevel="signature"`: читать могут только приложения с тем же ключом подписи. Запись снаружи невозможна
  (`insert`/`update`/`delete` бросают исключение). Дополнительно разрешение проверяется в коде провайдера.
* Адреса: `content://ru.diary.training.provider/{meta|days}` и `content://ru.diary.nutrition.provider/{meta|days}`;
  `days?from=yyyy-MM-dd&to=yyyy-MM-dd` отдаёт строку на каждую дату диапазона.
* «Тренировки» отдают по дням: ккал на занятиях (оценка пользователя), минуты, тип дня по плану, название тренировки;
  в `meta`: последний вес и флаг нормы белка.
* «Рацион» отдаёт по дням: ккал, белки, жиры, углеводы, число приёмов; в `meta`: цели по ккал и белку.
* Изменения: после записи вызывается `notifyChange`, клиент слушает `ContentObserver` плюс события установки и удаления пакета,
  поэтому данные обновляются без перезапуска, в том числе когда второе приложение ставят или удаляют во время работы.
* На Android 11+ второе приложение объявлено в `<queries>`. Любая ошибка (нет приложения, другая подпись, сбой провайдера)
  превращается в «интеграции нет»: блоки просто скрываются.
* Расход ккал — **оценка пользователя на занятиях**, а не общий расход; базовый обмен не считается, баланс не является медицинским выводом.

## Автообновление

Оба приложения сами ищут новую версию в **публичных** выпусках (Releases) этого репозитория: при запуске, не чаще раза в 12 часов,
и по кнопке в Настройки → Обновления. Найденный APK скачивается автоматически, затем показывается диалог «Установить».
Полностью тихая установка на Android невозможна без системных прав, поэтому последний шаг подтверждает пользователь
(при первом обновлении нужно разрешить приложению «Установка неизвестных приложений»). Во время тренировки диалог откладывается.

Перед предложением установки проверяются: только https и хосты GitHub, имя пакета, версия выше установленной,
**подпись такая же, как у установленного приложения**, и SHA-256 из GitHub, если он указан.
Поэтому обновление принимается только из релиза, собранного тем же ключом.

### Как выпустить новую версию

1. Поднять `diary.version` в `gradle.properties` (например, `0.3.0`).
2. Собрать подписанные APK тем же ключом, что и раньше: `./gradlew assembleRelease` (ключ из `local.properties`).
3. На GitHub: Releases → Draft a new release → тег `v0.3.0` (совпадает с `diary.version`) → приложить два файла **с точными именами**
   `app-training-release.apk` и `app-nutrition-release.apk` → Publish release.
4. Телефоны подхватят версию при следующем запуске приложения.

Первый переход с debug-сборки на release требует переустановки (разные ключи подписи): сначала сделайте экспорт JSON в настройках.

## CI/CD (GitHub Actions)

* `.github/workflows/ci.yml`: при каждом пуше в `main` и в запросах на слияние запускает `lint` и сборку debug обоих приложений.
* `.github/workflows/release.yml`: при пуше в `main` (если релиза с текущей `diary.version` ещё нет), при пуше тега `v*` или при ручном запуске собирает **подписанные** release-APK и публикует релиз с файлами
  `app-training-release.apk` и `app-nutrition-release.apk` (имена ищет автообновление). Тег должен совпадать с `diary.version`
  в `gradle.properties`, иначе сборка остановится.

Нужные секреты репозитория (Settings → Secrets and variables → Actions): `DIARY_KEYSTORE_BASE64` (файл `.jks` в base64),
`DIARY_KEYSTORE_PASSWORD`, `DIARY_KEY_ALIAS`, `DIARY_KEY_PASSWORD`.
Выпуск версии: поднять `diary.version`, закоммитить и запушить, затем `git tag v0.2.3 && git push origin v0.2.3` или запустить Actions → Release → Run workflow (тег создастся сам). Проще всего — поднять `diary.version` и влить изменения в `main`: релиз выпустится автоматически, если такой версии ещё нет.

## Совместимость с веб-версией

JSON-экспорт и импорт совместимы с прототипами (`dnevnik-trenirovok` `version: 3`, `dnevnik-raciona` `version: 1`).
Импорт очищает значения как `clean*`-функции прототипа, повреждённые записи пропускает и показывает их число;
режимы «заменить» и «объединить» повторяют `applyImport`. Старые типы занятий `handstand`, `stretch`, `pullday` превращаются в `track`.

## Отличия от веб-версии

* В реальном `raciona.html` нет меню на 2 недели, списка покупок, заморозки, обеда в колледже, графика вт–сб и режима 80/20;
  перенесено то, что есть в коде (20 блюд с рецептами и КБЖУ, дневник, «вне плана», неделя, свои блюда).
* В журнале рациона нет жиров и углеводов: для обмена данными они считаются по каталогу блюд, для записей вне плана и своих блюд равны 0.
* У встроенных домашних занятий всегда заполнена иконка, а у «подходов за день» длительность по умолчанию 20 (в веб-версии это происходит после первого импорта).
* Облачное хранилище веб-версии (`window.claude`) не переносилось: на телефоне данные только локальные.
